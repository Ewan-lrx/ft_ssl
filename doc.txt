MD5 ALGO:

Vue d'ensemble
	- pad le message pour qu'il devienne un multiple de 512bits (premier bits apres 	le message = 1 et les autres = 0)
	- initialiser 4 blocs de 32 bits (A, B, C, D) avec des valeurs fixes
	- le message est traite par blocs de 512 bits, chaque bloc modifiant les registr	es 64 fois.

Etape 1 (padding):
	- ajouter un bit 1 a la fin du message
	- rajoutes des 0 jusqu'a ce que la longueur du message soit congrue a 448 mod 51	2
	- ajouter la longueur initiale du message en bits, codee sur 64 bits, en little-	endian.

Etape 2 (constantes d'initialisation):
	- Les 4 registres de 32 bits sont initialisés en little-endian avec :
	A = 0x67452301
	B = 0xefcdab89
	C = 0x98badcfe
	D = 0x10325476
	- Il y a aussi une table de 64 constantes K[0..63], dérivées des sinus des entie	rs (tu peux les précalculer et les mettre en dur dans un tableau, c'est ce que t	out le monde fait — recalculer avec sin() demanderait math.h, ce qui casse la co	ntrainte des fonctions autorisées).
	- Il y a aussi une table de décalages S[0..63] (le nombre de bits pour la rotati	on à gauche à chaque round), qui se répète par groupes de 16.

Étape 3 : Traitement de chaque bloc de 512 bits
Pour chaque bloc de 512 bits :

On le découpe en 16 mots de 32 bits M[0..15] (en little-endian).
On sauvegarde une copie des registres actuels : AA, BB, CC, DD = A, B, C, D.
On fait tourner 64 rounds (indices 0 à 63), organisés en 4 groupes de 16 rounds, chacun utilisant une fonction non-linéaire différente :

RoundFonctionFormule0–15F(B & C) | (~B & D)16–31G(D & B) | (~D & C)32–47HB ^ C ^ D48–63IC ^ (B | ~D)
À chaque round i :
F = fonction_du_groupe(B, C, D)
F = F + A + K[i] + M[indice_du_mot(i)]
A = D
D = C
C = B
B = B + rotation_gauche(F, S[i])
L'indice du mot M[] utilisé dépend du round et du groupe (ce n'est pas juste i % 16, il y a une formule différente pour chaque groupe — c'est un des détails à bien vérifier dans une référence fiable comme le RFC 1321).

Une fois les 64 rounds terminés pour le bloc :

A += AA
B += BB
C += CC
D += DD
(avec overflow modulo 2^32, donc en pratique juste avec des uint32_t qui wrap naturellement en C).

Étape 4 : Résultat final
Une fois tous les blocs traités, le hash final est la concaténation de A, B, C, D en little-endian, ce qui donne les 16 octets (32 caractères hexa).
